# Validation performed

Validated on Windows 11 with Python 3.12.16, PySide6 6.12.0, PyAudioWPatch 0.2.12.9, and the downloaded FFmpeg essentials build on November 3, 2026.

- Automated suite: 100 passing tests covering the original editor/export/capture behavior plus replay retention and leases, independent hotkey IDs, concurrent manual recording and clipping, exact selected timestamps, real segment assembly at 15/24/30/60 FPS, two-minute selections, missing-segment errors, synthetic audio synchronization, and automatically saved clips trimmed to their requested selection at all four frame rates.
- Native replay checks passed with software H.264 and automatic AMD AMF selection, using the default Corsair WASAPI system-audio device. A single capture PID served a normal recording, a warm-up clip, and a full two-second clip; capture continued afterward, old segments expired, and disabling replay deleted the buffer. Tests establish audio capture/mux lifecycle, not audible hardware latency.
- The complete native tray workflow passed: a replay clip finished in the background, stopping manual recording opened the independent editor while replay continued, closing the editor preserved replay, and Quit removed temporary clips and capture files.
- Background workflow: hidden launch, shortcut start/stop, automatic editor opening, close-to-tray, recording again after stopping, and persisted keybind changes. Conflicting global shortcut replacements retain the old registration. Native Windows registration and delivery through Qt's WM_HOTKEY event filter were verified independently without synthesizing keystrokes.
- Full native tray smoke check passed: posted the registered shortcut's native messages to start and stop a real two-second GDI capture, verified the editor opened automatically, sought the preview, saved a screenshot of the compact layout, closed the editor, confirmed the tray remained active, and quit cleanly.
- Cleanup smoke check passed on Windows: after actual capture and preview playback, Quit released the decoder, removed the temporary recording, and exited. Unit/integration tests also verified that successful exports remain intact even when deliberately saved inside a session folder under an intermediate filename.
- Memory lifecycle: native before/after profiling measured post-editor working set at 244.64 MiB originally and 58.31 MiB with the on-demand editor process. A second close returned to 58.32 MiB. The tray never imported Qt Multimedia. See MEMORY.md for startup, active-preview costs, private commit, and methodology.
- Final Windows executable diagnostic passed twice: the final build used 51.16 MiB at startup and 55.86/55.88 MiB after successive editor closes. Both spawned editors exited, edit state returned, and no Multimedia module was imported into the tray process. The archive was checked to confirm it contains the latest command-reader implementation.
- Real media: all eight export formats; trim/crop dimensions and durations; VFR frame timestamps retained without added/dropped frames in MP4; explicit 15/24/30/60 FPS exports; positive/negative audio mux offsets; trimmed audio event timing.
- Native GDI desktop recording: 1920 × 1080, 30 FPS requested, successful graceful stop and valid finalized video. Actual captured timing varies with desktop capture/encoder load.
- Native WASAPI loopback: default Corsair headset output detected and opened; screen/audio recording finalized successfully with an AAC audio track. The output was silent during this short run; this verifies capture/mux lifecycle, not audible hardware latency.
- Native Windows UI: imported the captured recording, sought to 0.5 seconds, rendered the video preview, and visually inspected the editor. Qt's offscreen plugin rendered missing font glyphs in this environment; native Windows rendering displayed the intended typography correctly. The recording screen has been replaced by the tray menu.
- Appearance update: removed the application stylesheet and custom widget metrics. Visually verified native Windows controls with a black palette and green accent, no time-field arrows, and the visible `0.5s/3.1s` playback indicator. The supplied `seer_logo.png` replaces the drawn tray icon and is packaged as the window/tray image and Windows executable icon.
- Tray menu: Windows CreatePopupMenu/TrackPopupMenuEx now render the tray's context menu instead of a Qt popup. Opened, captured, visually inspected, and dismissed the real native menu; its standard light background, text, separators, and submenu arrows match Windows defaults even with the editor's dark palette active.
- PyInstaller directory build completed with FFmpeg and FFprobe included.

Not established by these checks: microphone hardware capture, human-perceived A/V synchronization, long-session drift, all device drivers, 4K/60 FPS performance, multi-DPI hardware configurations, protected content, or unplugging a device during capture. See README for precise local test steps. Synthetic audio event tests verify the offset and export algorithms independently of hardware latency.

Generated media, screenshots, downloaded tooling, virtual environments, and build output are ignored by source control.
